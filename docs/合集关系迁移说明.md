# 合集关系迁移说明

此说明适用于从 1.2.1 或更早版本升级到 1.2.2 的已有媒体库。全新安装无须迁移。

## 新规则

合集成员由两部分组成：

- 作品笔记的 `collections`：作品直接加入的合集。
- 系列笔记的 `collections`：该系列全部作品继承的合集。

两种来源会合并显示并去重。作品更换系列时，继承结果随之变化；作品自己的直接合集归属保持不变。

旧版在某些操作中会把系列的合集复制到每篇作品上，也会根据“某系列的全部作品是否加入合集”自动绑定或解绑系列。1.2.2 移除了这些隐式同步。升级不会自动删除已有关系，因为同一条关系也可能是用户希望永久保留的直接归属。

## 检查旧数据

先备份整个 Obsidian 库并等待同步完成。新建一个临时笔记，粘贴并运行下面的 DataviewJS；它只列出可能重复的关系，不会修改文件：

```dataviewjs
const works = dv.pages('"媒体库/作品"').where(page => page.note_type === "media").array();
const groups = dv.pages('"媒体库/合集"').where(page => page.note_type === "media_collection").array();
const toArray = value => !value ? [] : Array.isArray(value) ? value : typeof value.array === "function" ? value.array() : [value];
const pathOf = value => String(value?.path ?? value ?? "")
  .replace(/^\[\[/, "").replace(/\]\]$/, "").split("|")[0].replace(/\.md$/i, "");
const pointsTo = (value, page) => {
  const path = pathOf(value);
  return path === page.file.path.replace(/\.md$/i, "") || path === page.file.name || path.endsWith(`/${page.file.name}`);
};

const rows = [];
for (const work of works) {
  const series = groups.find(group => group.collection_kind === "series" && pointsTo(work.series, group));
  if (!series) continue;
  for (const collection of groups.filter(group => group.collection_kind === "collection")) {
    const direct = toArray(work.collections).some(value => pointsTo(value, collection));
    const inherited = toArray(series.collections).some(value => pointsTo(value, collection));
    if (direct && inherited) rows.push([work.file.link, series.file.link, collection.file.link]);
  }
}

dv.table(["作品", "所属系列", "重复合集"], rows);
```

逐条判断表中的关系：

- 希望作品跟随系列变化：从作品的 `collections` 中移除该合集，只保留系列笔记中的关系。
- 希望作品离开系列后仍保留在合集：保留作品的 `collections`，允许它同时显示为直接加入和系列继承。

## 验证

重新加载 Obsidian 后检查：

1. 作品页分别显示“系列继承”和“直接加入”。
2. 合集页的成员来源标记正确，“管理系列”和“直接添加作品”可用。
3. 临时取消某个系列的合集归属时，纯继承作品随之移出，直接加入的作品继续保留。
4. 恢复测试关系，并确认合集索引与合集详情的成员数量一致。
