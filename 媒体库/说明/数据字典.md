# 媒体库数据字典

这份文档统一说明媒体库各字段的含义、填写规则和边界。作品页、合集页、搜索与回顾视图都应以这里的定义为准。

字段分成三类：

- **作品资料**：作品本身是什么，例如标题、发行日期、作者和片长。
- **个人记录**：我与作品的关系，例如状态、进度、评分和完成日期。
- **组织关系**：作品如何归入系列、合集，以及作品之间如何关联。

未知数据应保持为空，不要用 `0`、当前日期或猜测值代替。只有进度确实为零时，进度字段才填写 `0`。

## 时间字段

| 字段 | 类型 | 含义 | 填写规则 |
| --- | --- | --- | --- |
| `release_date` | 文本 | 作品首次发行或上映的日期 | 可以只写年份，也可以写完整日期；未知时留空。它描述作品，不描述我何时体验 |
| `added_at` | 日期 | 作品首次加入个人媒体库的日期 | 创建作品记录时填写，之后通常不修改 |
| `started_at` | 日期 | 我实际开始这次主要体验的日期 | 首次进入“进行中”时可自动补齐；已有值时不覆盖 |
| `finished_at` | 日期 | 当前这一次体验的完成日期 | 只有确认完成时才补齐；重新打开当前记录或开始下一次体验时清空，历史日期由体验记录保留 |
| `last_activity_at` | 日期 | 当前体验最近一次开始或推进进度的日期 | 状态切换和普通资料编辑不改变它；用于可靠地判断最近体验 |
| `ended_at` | 日期 | 一条历史体验结束的日期 | 与 `result` 一起表示完成或弃置发生的时间 |
| `created_at` | 日期 | 系列、合集或历史体验记录的创建日期 | 不等同于作品的加入日期，也不代替体验的开始、结束日期 |
| `file.ctime` | 系统时间 | Obsidian 文件的创建时间 | 仅作缺失数据时的技术兜底，不作为正式业务字段 |
| `file.mtime` | 系统时间 | 文件最近一次被编辑的时间 | 可以表示“最近编辑”，不能当作开始、完成或观看日期 |

例如：

```yaml
release_date: "2016"
added_at: 2026-08-10
started_at: 2026-08-12
finished_at: 2026-08-13
```

这里表达的是：作品在 2016 年发行，我在 2026 年 8 月 10 日把它加入媒体库，两天后开始，并在次日完成。

作品记录始终保存当前这一次体验；完成或弃置后，页面会为它生成独立历史记录。旧作品缺少次数字段时按第一次体验处理，不会因为打开页面而批量改写。

## 重复体验记录

重复体验由作品详情页统一管理。作品负责当前状态，系统生成的体验记录负责历史，两者不能同时手工维护。

### 数据归属

- 作品记录继续保存作品资料，以及**当前这一次**体验的状态、进度、日期和当前评分。
- 体验记录只保存已经完成或弃置的一次历史快照，不承担当前状态。
- 暂停仍属于当前体验，不生成历史记录。
- 普通作品列表只查询 `note_type: media`；历史与回顾页面查询 `note_type: media_experience`。

这种划分确保当前状态只有作品一处可以编辑，历史记录由页面自动生成，不要求手工同步两套数据。

### 作品上的次数字段

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `experience_index` | 数字 | 当前是第几次体验，从 1 开始；只有明确点击“开始重看 / 重玩 / 重读”才增加。旧作品缺失时按 1 处理 |
| `last_activity_at` | 日期 | 当前体验最近一次实际推进进度的日期；用于“最近看过 / 玩过”，不使用 `file.mtime` 代替 |

进度从满值减少表示修正或重新打开**当前这一次**，不会增加 `experience_index`；重复体验功能启用后，此操作还应清除当前的 `finished_at`。暂停后继续也仍是同一次体验。明确开始下一次体验时，上一条记录先冻结，作品页再清空当前评分、进度和本次日期，避免上一轮评分被误当成新一轮评分。

### 历史体验记录

历史体验记录保存在 `媒体库/记录/`，使用以下字段：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `note_type` | 文本 | 固定为 `media_experience` |
| `work` | 链接 | 对应的作品记录 |
| `experience_index` | 数字 | 这是该作品的第几次体验，必须与作品内的次数保持唯一 |
| `result` | 文本 | 已结束结果：`completed` 或 `abandoned` |
| `record_origin` | 文本 | 记录来源：正常使用功能生成时为 `tracked`，从旧作品补齐时为 `migrated` |
| `date_certainty` | 文本 | 结束日期可信度：`exact`、`approximate` 或 `unknown`；只描述 `ended_at` 是否可靠，不评价其他字段 |
| `year_verified` | 布尔值 | 记录所属年份是否已经由本人确认；只有 `true` 才能进入正式年度统计 |
| `verified_year` | 数字 | 本人确认的体验年份；精确日期和只确认年份的记录都填写，未确认时留空 |
| `started_at` | 日期 | 这次体验的开始日期；不确定时留空，不能为了凑成日期区间复制或保留明显冲突的日期 |
| `ended_at` | 日期 | 这次体验完成或弃置的日期 |
| `progress_value` | 数字 | 结束时到达的进度 |
| `progress_total` | 数字 | 当时采用的总量 |
| `progress_unit` | 文本 | `page`、`episode`、`minute` 或 `percent` |
| `experience_rating` | 数字 | 这次体验结束时的评分快照；未单独评分时留空 |
| `edition` | 文本 | 本次使用的版本，例如导演剪辑版、重制版或特定书籍版本 |
| `played_on` | 列表 | 游戏本次实际游玩的平台；与作品的发行平台 `platforms` 分开 |
| `created_at` | 日期 | 历史记录生成的日期 |

示例：

```yaml
note_type: media_experience
work: "[[媒体库/作品/疯狂动物城（2016）|疯狂动物城]]"
experience_index: 2
result: completed
record_origin: tracked
date_certainty: exact
year_verified: true
verified_year: 2027
started_at: 2027-05-01
ended_at: 2027-05-03
progress_value: 108
progress_total: 108
progress_unit: minute
experience_rating: 5
edition:
played_on: []
created_at: 2027-05-03
```

历史记录的唯一键是 `work + experience_index`。重复保存必须更新同一条记录，不能创建重复次数。当前体验确认结束时生成历史快照；如果随后重新打开同一次体验进行修正，应暂时撤销这条快照，重新确认结束后再生成。只有点击“开始下一次体验”后，上一条记录才成为冻结历史。

`rating` 表示作品当前这一次体验所采用的评分，`experience_rating` 表示某一次结束时的评分快照。当前次数尚未进入下一次体验时，两者双向同步；点击“开始重看 / 重玩 / 重读”后，上一条记录冻结，之后修改作品评分不会回写旧次数。

由旧版本迁移生成的记录使用 `record_origin: migrated`。旧作品已有的开始、结束日期只能证明它们是原记录中的日期，无法证明当时曾被精确追踪，因此迁移时标记为 `date_certainty: approximate`；没有可用结束日期时保留为空，并标记为 `unknown`，不使用迁移当天冒充体验日期。迁移记录初始使用 `year_verified: false` 且不填写 `verified_year`，经过本人确认后仍保留 `record_origin: migrated`，只更新日期可信度和确认年份。记录来源不能代替真实性判断。

年度回顾以 `year_verified: true` 和 `verified_year` 为年份依据。`verified_year` 表示体验结束的归属年份：精确记录自动取 `ended_at` 的年份，一条记录只进入一个年度。`started_at` 与 `ended_at` 不在同一年时，页面自动标记为跨年完成或跨年弃置，不拆分成多条记录，也不在经过的每一年重复统计。`date_certainty: exact` 的记录可以进入月份时间线；只确认年份的 `approximate` 记录计入年度总数，但不参与月份趋势。正常使用详情页确认完成或弃置时生成的 `tracked` 记录，会自动写入精确日期和确认年份；当天新增作品并如实标记为已完成，也属于这种真实记录。年度“完成规模”按结束年份归集已完成记录的页数、集数、时长或游戏数量，它表示该年结束的体验规模，不要求使用者拆分跨年过程。

校准历史记录的准确日期时，如果记录的 `experience_index` 与作品当前次数相同，并且作品仍是对应的已完成或弃置状态，应同步作品的 `started_at`、`finished_at` 和 `last_activity_at`。较早次数的记录只修改历史快照，不能覆盖作品当前体验；只确认年份也不能反推具体日期。

历史记录文件不是只供统计读取的空壳。记录页应展示本次结果、日期、评分、结束进度、版本、游玩平台和可信度，并允许本人纠正。只有“作品当前次数与记录次数相同、作品当前状态与记录原结果一致”才同步作品的共用数据；否则只修改历史快照。共用数据包括状态与结果、作品评分与本次评分、日期和对应进度，其中只有精确日期可以回写作品的具体日期。作品与当前记录遵循最后一次修改生效；较早次数始终冻结。

## 状态、进度与个人评价

### `status`

`status` 表示我当前如何对待这部作品，是用户作出的判断，不应只根据进度机械推断。

| 值 | 含义 |
| --- | --- |
| `待体验` | 已加入媒体库，但还没有正式开始 |
| `进行中` | 正在阅读、观看或游玩 |
| `已完成` | 已由我确认完成本次体验 |
| `暂停` | 暂时停止，但仍打算继续 |
| `弃置` | 已决定停止，当前不打算继续 |

进度达到 100% 时，界面应提示确认是否完成；只有确认后才把状态改为 `已完成` 并补齐 `finished_at`。从满进度往回减少时，状态可以恢复为 `进行中`，但不自动删除已经发生过的完成日期。

### 进度字段

| 媒体类型 | 当前进度 | 总量 | 单位 |
| --- | --- | --- | --- |
| 书籍 | `current_page` | `page_count` | 页 |
| 电影 | `current_minutes` | `runtime_minutes` | 分钟 |
| 电视剧 / 动漫 | `current_episode` | `episode_count` | 集 |
| 游戏 | `progress_percent` | 固定为 100 | 百分比 |

这些字段只保存数字，不附带“页”“集”“分钟”或 `%`。旧导入数据中如果存在“142分钟”一类文本，当前页面可以兼容读取，但新数据应逐步统一为纯数字。

总量未知时保持为空。此时可以记录当前进度，但页面不能据此计算准确百分比。

### `rating`、`source_rating` 与 `favorite`

| 字段 | 含义 | 规则 |
| --- | --- | --- |
| `rating` | 我的个人评分 | 采用 0.5–5 星；空值表示未评分，`0` 不代表未评分 |
| `source_rating` | 外部数据源的评分 | 保留来源网站的原始量表，通常是 10 分制；不能与个人评分直接混排 |
| `favorite` | 个人收藏标记 | 表示我想重点保留或快速找到这部作品；与评分、状态相互独立 |

一部作品可以评分很高但没有标记收藏，也可以因为私人意义被收藏但评分不高。

## 作品身份与显示字段

| 字段 | 含义 |
| --- | --- |
| `note_type` | 记录类型。作品固定为 `media`，系列与合集固定为 `media_collection`；预留的历史体验记录使用 `media_experience` |
| `media_type` | 作品类型：`book`、`movie`、`tv`、`anime`、`game`、`variety`、`documentary` |
| `media_format` | 内部记录方式：`book`、`movie`、`series`、`game`；旧作品缺失时会根据 `media_type` 自动推断 |
| `title` | 页面和卡片使用的主标题 |
| `original_title` | 作品的官方原名；没有明确原名时留空 |
| `aliases` | 其他常用译名、简称或搜索别名 |
| `cover` | 竖版封面的本地路径 |
| `backdrop` | 横幅或背景图的本地路径 |
| `backdrop_position` | 横幅的显示位置，由作品页的拖动预览自动记录 |
| `backdrop_scale` | 横幅相对铺满尺寸的缩放比例；默认 1，缩小时以同图柔化背景填充空白 |
| `genres` | 作品的题材或类型标签，例如“科幻”“冒险” |
| `description` | 系列或合集的简介；作品的长笔记仍写在正文中 |
| `tags` | Obsidian 原生标签；当前正式视图不依赖它，不用它代替 `media_type` 或 `genres` |
| `cssclasses` | 页面样式所需的内部字段，不承载作品资料 |

`media_type` 回答“用户如何分类它”，`media_format` 决定页数、时长、集数或百分比进度，`genres` 回答“它讲什么或属于什么题材”。例如纪录剧集的 `media_type` 是 `documentary`，`media_format` 是 `series`；《疯狂动物城》仍归入 `movie`，`genres` 中保留 `动画`。

## 系列、合集与关联作品

这是最容易混淆的一组字段，统一按下面的规则理解：

| 字段 | 使用位置 | 含义 |
| --- | --- | --- |
| `collection_kind` | 合集记录 | `series` 表示系列，`collection` 表示普通合集 |
| `series` | 作品记录 | 作品直接所属的一个系列 |
| `collections` | 作品记录 | 作品被直接加入的普通合集，不包含从系列继承的合集 |
| `collections` | 系列记录 | 整个系列归属的普通合集；系列内作品会在这些合集中继承显示 |
| `related` | 作品记录 | 与当前作品有关，但不构成系列或合集归属的其他作品 |
| `source_series` | 作品记录 | 外部数据源提供的系列文字，仅作原始资料，不参与媒体库归属判断 |
| `sequence` | 作品记录 | 预留的手工顺序字段；当前页面没有依赖它，暂不填写 |

普通合集记录自身的 `collections` 目前保持为空。系列最多有一个直接归属，即作品的 `series` 是单值；一部作品可以直接加入多个普通合集，因此作品的 `collections` 是列表。

### 例子

假设有系列“疯狂动物城系列”，普通合集“适合周末看的电影”：

```yaml
# 作品：疯狂动物城.md
series: "[[疯狂动物城系列]]"
collections: []

# 系列：疯狂动物城系列.md
collection_kind: series
collections:
  - "[[适合周末看的电影]]"
```

此时作品会出现在“适合周末看的电影”中，但这是**通过系列继承**，所以修改归属要去系列页操作。

如果某部单独作品直接加入该合集，则写成：

```yaml
series:
collections:
  - "[[适合周末看的电影]]"
```

这种归属与任何系列无关，可以直接在合集页移除。以后作品更换系列时，这条直接归属仍然保留。

`related` 用于“值得互相跳转，但没有归属关系”的情况，例如改编作品、重制版或主题相关作品。通过页面操作维护时应保持双向关联。

## 来源字段

| 字段 | 含义 |
| --- | --- |
| `source` | 记录来源，例如 `manual` 或 `douban` |
| `source_id` | 该来源中的作品编号 |
| `source_url` | 来源页面地址 |
| `source_rating` | 来源网站的评分，保留原量表 |
| `imdb_id` | IMDb 作品编号 |
| `isbn` | 书籍 ISBN |

来源字段用于追溯和更新作品资料，不决定个人状态、进度、评分、收藏和归属关系。重新导入资料时，也不应覆盖这些个人记录字段。

## 各媒体类型的专属字段

### 书籍

| 字段 | 含义 |
| --- | --- |
| `authors` | 作者列表 |
| `translators` | 译者列表 |
| `publisher` | 出版社 |
| `isbn` | ISBN |
| `source_series` | 来源网站给出的丛书或系列文字，不等同于媒体库 `series` |
| `page_count` | 总页数 |
| `current_page` | 当前读到的页数 |

### 电影

| 字段 | 含义 |
| --- | --- |
| `directors` | 导演列表 |
| `screenwriters` | 编剧列表 |
| `cast` | 主要演员列表 |
| `country` | 制片国家或地区 |
| `language` | 主要语言 |
| `imdb_id` | IMDb 编号 |
| `runtime_minutes` | 总片长，单位为分钟 |
| `current_minutes` | 当前看到的位置，单位为分钟 |

### 电视剧与动漫

| 字段 | 含义 |
| --- | --- |
| `directors`、`screenwriters`、`cast` | 主创信息；有数据时填写 |
| `country`、`language`、`imdb_id` | 来源资料；有数据时填写 |
| `episode_count` | 当前记录范围内的总集数 |
| `season_count` | 全剧季数；未知时留空 |
| `current_episode` | 当前看到的集数 |
| `format` | 动漫的发行形式，例如 TV、剧场版、OVA；它不替代 `media_type` |

对于按季分别建档的电视剧，`episode_count` 表示这一季的集数；对于整部剧只建一条记录的情况，它表示该记录覆盖范围内的总集数。两种做法可以并存，但同一系列内应保持一致。

### 游戏

| 字段 | 含义 |
| --- | --- |
| `platforms` | 作品发行或支持的平台列表；当前字段不表示我实际使用的平台 |
| `developer` | 开发商 |
| `progress_percent` | 我的游玩进度，范围为 0–100 |

## 空值与数据格式

- 未知文本保持为空，不写“未知”“暂无”。
- 未知数字使用空值或 `null`；确实从零开始的进度可以写 `0`。
- 未评分使用 `rating: null`，不使用 `rating: 0`。
- 多值字段没有内容时写 `[]`，例如 `genres: []`、`collections: []`。
- 布尔字段使用 `true` / `false`，例如 `favorite: false`。
- 关系字段使用 Obsidian 双链，避免只写无法跳转的普通文本。
- 日期使用 `YYYY-MM-DD`；只有 `release_date` 因来源精度不一致而保留为文本，可以只写 `YYYY`。
- 页数、集数、分钟和百分比字段保存纯数字，单位由页面负责显示。

## 视图应如何使用这些字段

| 想回答的问题 | 应使用的字段 |
| --- | --- |
| 最近加入了什么 | `added_at` |
| 最近完成了什么 | `finished_at` |
| 最近实际推进了什么 | `last_activity_at` |
| 最近编辑了哪些记录 | `file.mtime` |
| 某年发行了什么 | `release_date` |
| 正在体验什么 | `status: 进行中`，再结合相应进度字段 |
| 我最喜欢什么 | `favorite: true` |
| 我的高分作品 | `rating`，不要使用 `source_rating` |
| 某合集有哪些成员 | 作品的直接 `collections`，加上系列继承关系 |
| 某年重看、重玩或重读了什么 | 历史体验记录的 `ended_at` 与 `result` |

这也是后续设计搜索和回顾入口时的依据。尤其要避免用 `file.mtime` 冒充“最近看过”，因为改个封面也会改变它。
